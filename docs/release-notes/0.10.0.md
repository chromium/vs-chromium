# VsChromium 0.10.0

VsChromium 0.10.0 is a major update. The indexing server has been rewritten on portable .NET 10.
It now runs on Windows, Linux and macOS, and it powers a new VS Code extension as well as the
Visual Studio extension. Both extensions share a new server dashboard.

## Highlights

- **New VS Code extension** (Windows, Linux, macOS), with the same instant indexed code search as
  the Visual Studio extension.
- **Portable, self-contained server.** The server is a single executable for each platform, built
  on .NET 10 and bundled with the extensions. No .NET runtime to install, and no native code.
- **Server dashboard**, the same page in VS Code and in Visual Studio. It shows the status, memory,
  charts and settings of each project, and has a disk usage explorer.
- **Index cache.** After a restart, the index is searchable in well under a second, then it is
  verified in the background.
- **Faster startup on Windows.** The server verifies the index cache from the NTFS change journal,
  so it no longer rescans the whole tree.
- **Faster searches and updates.** Optional trigram filters make selective searches 10-18x faster,
  and file changes reach the index 2-3x faster.

## VS Code

- New extension, published as one package per platform: `win32-x64`, `win32-arm64`, `linux-x64`,
  `linux-arm64`, `darwin-x64` and `darwin-arm64`. Each package bundles the server for its platform.
- It activates in workspaces that contain `vs-chromium-project.txt` or `.gn`.
- **Code Search** panel ("VsChromium - Code Search").
  - **Search Code**: `Ctrl+Alt+;`
  - **Find File Names**: `Ctrl+Alt+'`
- Commands: **Show Indexing Server Status** (opens the dashboard), **Restart Indexing Server**,
  **Show Output** and **Toggle Trigram Filters**.
- The status bar shows the state of the server and of the index cache.
- Settings: index cache (`vschromium.cacheEnabled`, `vschromium.cacheDirectory`), trigram filters,
  watching of external symbolic link targets, search limits and `vschromium.serverPath`. Most
  settings can be set per workspace folder.

## Visual Studio

- Supports Visual Studio 2022 (17.0 and later) and Visual Studio 2026. There is a single VSIX for
  **x64 and ARM64** Visual Studio.
  - On ARM64 Windows, the extension always starts the native ARM64 server, even when Visual Studio
    runs as an emulated x64 process.
- New **VsChromium Server** tool window: the server dashboard, hosted in WebView2. From there you
  can restart the server, open the log, rebuild a project, clear its cache, override project
  settings, and copy or add ignore patterns.
- New **Tools > Options > VsChromium > Index Server** page: trigram filters, index cache, cache
  directory, and watching of symbolic link targets outside the project.
- The extension starts the server directly and talks to it over standard input/output. There is
  no more TCP connection or host process.

## Server

- **Portable .NET 10 server**, published self-contained and ReadyToRun for each platform. It
  speaks JSON-RPC 2.0 over standard input/output. The protocol is defined in TypeSpec, and the
  server and client code is generated from it.
- **Index cache.** File contents and the project tree are saved on disk and memory-mapped when the
  server restarts.
  - The cache is saved when the index settles, and compacted and cleaned up automatically.
  - It can be turned off globally or per project. The cache directory must be on a local disk.
  - Default location: `%LOCALAPPDATA%\VsChromium\Cache` on Windows, `~/Library/Caches/VsChromium`
    on macOS, `$XDG_CACHE_HOME/vschromium` on Linux.
- **Change journal verification** (Windows, NTFS). At startup, only the directories that changed
  since the last run are listed again. The server falls back to a full scan when the journal is
  inactive or wrapped, and on network or FAT drives.
- **Symbolic links.** Changes to the targets of links update the index. Targets outside the project
  are watched only when you opt in, per project.
- **Disk usage explorer** in the dashboard. It shows the size of each directory, including excluded
  directories and symbolic links, and you can add ignore patterns to `vs-chromium-project.txt` with
  one click.
- **Trigram filters** (off by default, per project): a per-file index that makes selective searches
  much faster, at the cost of about 5% of the size of the text.
- **Indexing**
  - Paths longer than `MAX_PATH` are indexed.
  - UTF-16 files with a BOM are indexed as text.
  - Binary files are detected the way git detects them (a NUL byte in the first 8,000 bytes).
- **Search fixes**
  - Positions and patterns with non-ASCII text are now correct.
  - Regular expression anchors `^` and `$` now match at line boundaries.
  - Matches at chunk boundaries are no longer missed.
- **Linux**: when the inotify watch limit is reached, the server falls back to polling.
- Background indexing slows down a full-CPU build much less: 47% → 13% slowdown of the build in our
  measurements.
- **vschromium-bench**: a new portable benchmark tool for the indexing server. It generates a
  standard corpus, runs the scenarios, and writes reports you can share, without personal data.

## Performance

Unless noted, the numbers are for a generated corpus of 400,000 files (7.2 GB), compared with
0.9.39, on Windows with a warm file cache.

| Scenario | 0.9.39 | 0.10.0 |
| --- | --- | --- |
| Full index | 9.4 s | 8.0 s |
| Restart: index searchable (index cache) | 6.8 s (full load) | 0.8 s |
| Startup verification, a large project (2.65M files), change journal | 9.4-9.7 s (full scan) | 0.7-1.0 s |
| Selective code search (trigram filters on) | 100 ms | 6 ms |
| Common code search, ignore case (filters off, the default) | 194 ms | 129 ms |
| File name search `*.mojom` | 11.4 ms | 6.3 ms |
| Modified file visible in searches | 2.6 s | 0.8 s |
| Recovery after a 20,000-file checkout (watcher overflow) | > 70 s | ~4.5 s |

## Compatibility notes

- **Visual Studio 2015-2019 are no longer supported.** Use Visual Studio 2022 (17.0+) or 2026.
- **VS Code 1.100 or later** is required.
- **No .NET installation is needed.** The server bundled with each extension is self-contained.
- **New disk usage: the index cache.** On a large tree it can take several GB, about the size of
  the indexed text. You can disable it, or move it with the cache directory setting.
  - Caches of another format version are discarded and rebuilt automatically.
- **Indexing changes.** Files with a NUL byte in the first 8,000 bytes are now treated as binary,
  and UTF-16 files with a BOM are now searchable.
- **New protocol.** The server protocol is now JSON-RPC: servers and extensions of different
  versions can't be mixed.
- **Linux and macOS support is new and less tested than Windows.** Please report issues.
  - On macOS, the bundled executables are ad-hoc signed, not notarized.
